# 音频存档与转录缓存（audio_archive/）

*v3.0.0 引入，v3.3.1 起补上数据安全防线。*

每次录音的原始音频和转写结果都会自动留档，默认**全部保留、不自动清理**。这既是出问题时的排查素材，也是一份可以回头翻的个人语音记录。

## 目录分工

`audio_archive/` 下三样东西职责完全不同，别混为一谈：

| 位置 | 内容 | 谁写的 |
|------|------|--------|
| `audio/` | 语音输入热键录下的短录音，命名 `recording_YYYYMMDD_HHMMSS.wav` | `AudioArchiveManager.save_audio_bytes()` 自动写入 |
| `cache.json` | 上述录音的转写结果索引，key 是音频文件名 | `AudioArchiveManager.save_transcription_result()` 自动写入 |
| `transcribe/` | **手动跑大文件转录的独立工作区**（会议、访谈、长视频） | `test/transcribe_audio_doubao_speaker.py` 这类独立脚本 |

`transcribe/` 跟语音输入毫无关系，主程序不该碰它。历史上 `_migrate_legacy_archive_entries` 曾用黑名单迁移把它整个搬走过，现已改成白名单——**只搬音频扩展名的文件，目录一律不动**。

## cache.json 的结构

```json
{
  "recording_20260730_194326.wav": {
    "transcription": "把这些新的学问都记录到 Docs 里面。",
    "service": "doubao",
    "model": "bigmodel",
    "mode": "transcriptions",
    "timestamp": "2026-07-30T19:43:26.677000"
  }
}
```

`service` / `model` 反映实际走的后端（豆包流式、OpenAI、本地 whisper.cpp）。带 `"recovered_from_log": true` 的记录是从运行日志重建的，见下节。

## 数据安全

这份缓存曾在 2026-04-03 被程序自己清空过，丢了约 2900 条。现在有四道防线：原子写、上一代备份（`cache.json.bak`）、读失败绝不返回空字典、并发写加锁。

**看到 `cache.json.corrupt-<时间戳>` 不要慌**——那不是故障，是缓存被写坏后系统替你留下的原件，历史都在里面。

成因、防线细节、抢救办法见 **[转录缓存的数据安全](./TRANSCRIPTION_CACHE_SAFETY.md)**。

## 日常操作

```bash
# 看最近的录音
ls -lt audio_archive/audio/ | head

# 播放某条录音（macOS）
afplay audio_archive/audio/recording_20260730_194326.wav

# 查缓存条数
python -c "import json;print(len(json.load(open('audio_archive/cache.json'))))"

# 按关键词搜自己说过的话
python -c "
import json
for k, v in json.load(open('audio_archive/cache.json')).items():
    if '关键词' in v['transcription']: print(k, v['transcription'][:60])
"
```

## 清理

**不要 `rm -rf audio_archive/`**——那会连转录缓存和 `transcribe/` 工作区一起删掉，缓存删了就找不回来了。

只清音频、保留文字记录：

```bash
# 删 30 天前的录音（cache.json 里的文字记录不受影响）
find audio_archive/audio/ -name "*.wav" -mtime +30 -delete
```

备份（缓存是唯一不可再生的部分，值得单独备一份）：

```bash
cp audio_archive/cache.json ~/backup_cache_$(date +%Y%m%d).json
```

## 容量参考

单条录音约 32KB/秒，只增不减。一万多条短录音的量级大约是几个 GB 音频 + 5MB 缓存——缓存本身很小，占地方的是音频。

`audio_archive/` 已在 `.gitignore` 里，不会被误提交。
